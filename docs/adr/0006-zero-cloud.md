# Zero-cloud: Braid removes its cloud services

Braid had exactly two cloud touchpoints left: AssemblyAI transcribed and diarized the Recording, and Claude wrote the Note. Both are removed. The decision that forced the issue is the Voice Database ([ADR-0007](0007-the-voice-database.md)): storing voiceprints is defensible precisely because this is a private, single-owner app where nothing derived from a voice ever leaves the machine, and that premise is only honest if it is structural. An app that uploads audio to one service and transcript text to another is not that app. So transcription is the local pipeline ADR-0005 built (Apple SpeechTranscriber by default, Parakeet selectable, offline pyannote diarization), and summarisation moves to Apple's on-device foundation model with guided generation, map-reduced over chunks when a Transcript exceeds its context window. The Summariser sits behind the same kind of seam the Engines do, so a stronger local model can replace it if measurement says so.

Two real costs are accepted with eyes open, not discovered later. First, AssemblyAI's diarization measured better than local (it was the very reference our 61 to 71 percent turn-purity numbers were scored against); removing it means accepting worse attribution today and betting on the Voice Database plus Re-attribution to close the gap as the app learns its recurring speakers. Second, Opus-quality prose is given up: a 3B-class on-device model writes the Notes now. The bet is that Preset-structured extraction (Decisions, Action items, Key points) is the kind of constrained task small models do respectably, and the harness culture applies: summary quality is measured against kept fixtures, not assumed.

## Consequences

- **What disappears with the cloud**: both API keys and all account setup; the cost rate table, spend tracking, usage cap and cost frontmatter (nothing is metered because nothing costs anything); the FLAC transcode (it existed only for uploads); the network branch of the failure taxonomy; the Auto-fallback machinery and its disclosure. Setup is now: choose a Vault folder, grant audio permission.
- **Network posture**: the app performs no network I/O except fetching model assets (Parakeet models via FluidAudio, Apple speech assets via the OS). User data, audio, text, and anything derived from them never travel. The Done gate verifies the whole journey with Wi-Fi off.
- **ADR-0002 is now historical**; ADR-0005's local pipeline is what remains, its Cloud/Local/Auto provider modes and fallback are superseded by this decision. "Provider" leaves the vocabulary; the interchangeable local implementations are Engines.
- **The default Engine flips to Apple SpeechTranscriber**, on the evidence: 9 points better turn purity on the real-call fixture, Key Terms support, no model download. Parakeet stays selectable for its word-accuracy edge.
- **The on-device model refuses subjects, and this is the real cost of the decision.** Measured 2026-08-02 on a recorded podcast discussing named political figures and the Epstein case: the model declined the entire session. Not a guardrail — `permissiveContentTransformations` makes no difference, nor does the content-tagging use case, nor neutral "you are a transcription tool" instructions, nor turning guardrails back to default. `LanguageModelError.refusal` is the model's own training, and there is no setting that reaches it. Line by line, it refused two passages and summarised the other four quite happily, so the recovery is to slice finely, keep what it will take, and tell the reader plainly what is missing. A whole class of legitimate meeting content — politics, anything touching crime or allegations about named people, plenty besides — will summarise partially or not at all. Cloud models did not do this. If that class of recording matters, the answer is not a setting but a different summariser: an MLX-hosted open model has no such training, which is the option this ADR rejected on weight and now has a second reason to revisit. The Summariser seam is what keeps that a swap rather than a rewrite.
- **So there are two summarisers, and the choice is the user's.** Apple's stays the default: weightless, always present, and fine for most sessions. Beside it sits an open-weights model through MLX (Qwen3 4B by default, Gemma 3 4B and Qwen2.5 3B selectable), which has no such refusals — verified on the exact transcript Apple declined, which it summarised in full and correctly. It also carries 32k of context against Apple's ~4k, so an hour of meeting is summarised in one pass rather than as a summary of summaries. The costs are real and named in Settings: a 2.3GB download and roughly that much memory while it writes. This is the second and third dependency exception (mlx-swift-examples and its tree) and it required reversing ADR-0004; the seam this ADR insisted on is what made it an addition rather than a rewrite.
- **Structure has to be asked for rather than enforced.** Apple's path gets a generation schema; MLX has no constrained decoding, so it is asked for JSON — and small models return JSON with a bracket in the wrong place, wrapped in a code fence, behind a `<think>` block, or not at all. `ModelReply` in BraidCore recovers all of those, including reading fields out of JSON too broken to decode, because the alternative is raw JSON in the user's vault. It lives in BraidCore rather than beside the MLX code specifically so `swift test` can reach it.
- **Guided generation without the macro.** `@Generable`'s compiler plugin ships with Xcode, not with Command Line Tools, so ADR-0004's toolchain rules it out. `DynamicGenerationSchema` gives the same guided generation with the schema written by hand, which turned out to be the better shape anyway: Presets are user-editable (R12), so the Note's structure has to be built at runtime from whatever headings a Preset names rather than baked into a Swift type at compile time.
- **Presets had to be rewritten for it.** They previously told the model to emit markdown, start with an `# H1` and avoid code fences — instructions that contradict a schema and that a 3B-class model handles badly. They now name headings only, and Braid assembles the markdown. The separate "Summary" section every Preset used to request was dropped, because the schema already has a summary field and the first measured Note repeated itself.
- **Reversal path**: the cloud Adapters live in git history, and the seam they plugged into still exists. Coming back would be a revert plus re-keying, not a rebuild. It would also void ADR-0007's premise, so it is a decision, not a tweak.
